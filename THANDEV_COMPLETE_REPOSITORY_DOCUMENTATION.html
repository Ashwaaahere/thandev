Platform Overview

What is Thandev?

Thandev is a comprehensive, modern security intelligence platform that combines:

  1. Security Vulnerability Scanning - Multi-tier scanning with Nuclei, Nmap, SSLScan
  2. Performance Analysis - Google Lighthouse integration for web performance
  3. Security News Aggregation - Real-time feeds from certified sources
  4. CVE & Exploit Tracking - National Vulnerability Database integration
  5. Domain Verification - DNS-based ownership verification
  6. Multi-tenant SaaS - Enterprise-ready architecture

Core Value Proposition

Thandev solves the problem of fragmented security tooling by providing: - Unified Interface - One platform for all security needs - Automated Workflows - From scan to report automatically - AI-Powered Insights - RAG-based planning and reporting - Scalable Infrastructure - Cloud-native architecture - Developer-Friendly - Modern APIs and documentation

Platform Components

The platform consists of 5 main services:

  1. Backend API (backend/) - FastAPI service handling all business logic
  2. Frontend (frontend/) - Next.js web application
  3. Brain Service (services/thandev-brain/) - RAG-powered planning service
  4. Runner Service (services/thandev-runner/) - Tool execution service
  5. Cloud Run Services (cloud-run/) - Serverless scanning services

Service Communication Flow

1. User Initiates Scan:

User → Frontend → Backend API → Brain Service (plan) → Runner Service (execute) → Backend API → Frontend → User

2. Data Flow:

External APIs (NVD, RSS) → Scheduler → Backend API → PostgreSQL → Frontend → User

3. RAG Flow:

Findings → Brain Service → Embeddings → Qdrant → RAG Query → Enhanced Planning

Technology Stack Explained

Frontend Stack

Next.js 14: - What: React framework with server-side rendering - Why: Provides SEO, fast initial load, and modern React features - How: Uses App Router for file-based routing, Server Components for data fetching

TypeScript: - What: Typed superset of JavaScript - Why: Catches errors at compile-time, improves IDE support - How: All .tsx files are type-checked before compilation

Tailwind CSS 4: - What: Utility-first CSS framework - Why: Rapid UI development, consistent design system - How: Classes like bg-blue-500 generate CSS at build time

Backend Stack

FastAPI: - What: Modern Python web framework - Why: Fast performance, automatic API docs, async support - How: Uses Pydantic for validation, Starlette for async

SQLAlchemy 2.0: - What: Python ORM (Object-Relational Mapping) - Why: Type-safe database queries, migrations, connection pooling - How: Models map to tables, sessions manage transactions

Celery: - What: Distributed task queue - Why: Background processing, scalability, reliability - How: Redis as broker, workers execute tasks asynchronously

pool_config = {
    "poolclass": QueuePool,
    "pool_size": 10,
    "max_overflow": 20,
    "pool_pre_ping": True,  # Verify connections before using

Explanation: - QueuePool: Thread-safe connection pool - pool_size: 10 persistent connections - max_overflow: Up to 20 additional connections - pool_pre_ping: Tests connection before use (handles stale connections) - pool_recycle: Recreates connections after 1 hour (prevents timeout) - echo: Logs SQL queries (debugging) - future: Uses SQLAlchemy 2.0 style

# Connection retry logic
@event.listens_for(engine, "connect")
def set_sqlite_pragma(dbapi_conn, connection_record):
    """Set SQLite pragmas for better performance"""
    if not is_postgresql:
        cursor = dbapi_conn.cursor()
        cursor.execute("PRAGMA foreign_keys=ON")
        cursor.execute("PRAGMA journal_mode=WAL")
        cursor.close()

Explanation: - @event.listens_for: SQLAlchemy event listener - "connect": Fires when connection created - PRAGMA foreign_keys=ON: Enables foreign key constraints - PRAGMA journal_mode=WAL: Write-Ahead Logging (better concurrency)

def get_db():
    """Dependency for getting database session with retry logic"""
    db = SessionLocal()
    max_retries = 3
    retry_delay = 0.1
    
    for attempt in range(max_retries):
        try:
            # Test connection
            db.execute(text("SELECT 1"))
            yield db
            break
        except (OperationalError, DisconnectionError) as e:
            if attempt < max_retries - 1:
                logger.warning(f"Database connection failed, retrying... (attempt {attempt + 1}/{max_retries})")
                db.rollback()
                time.sleep(retry_delay * (attempt + 1))
                db = SessionLocal()
            else:
                logger.error(f"Database connection failed after {max_retries} attempts: {e}")
                db.rollback()
                raise
        finally:
            if attempt == max_retries - 1:
                db.close()

Explanation: - get_db(): FastAPI dependency (called per request) - yield db: Provides session, closes after request - Retry logic: Retries up to 3 times on connection failure - Exponential backoff: retry_delay * (attempt + 1) - db.close(): Closes session in finally block

# services/thandev-brain/app/rag/embeddings.py

class SentenceTransformersProvider(EmbeddingProvider):
    """Sentence Transformers embedding provider"""
    
    def __init__(self, model_name: str):
        self.model_name = model_name
        self._model = None
    
    async def embed(self, texts: List[str]) -> List[List[float]]:
        """Generate embeddings for texts"""
        if self._model is None:
            from sentence_transformers import SentenceTransformer
            self._model = SentenceTransformer(self.model_name)
        
        # Run in thread pool (model is CPU-bound)
        loop = asyncio.get_event_loop()
        embeddings = await loop.run_in_executor(
            None,
            self._model.encode,
            texts,
        )
        
        return embeddings.tolist()

Explanation: - Sentence Transformers: Local embedding model - SentenceTransformer: Loads pre-trained model - encode: Generates embeddings (CPU-bound) - run_in_executor: Runs in thread pool (doesn’t block event loop) - tolist(): Converts numpy array to Python list

Document Storage

    async def upsert_documents(self, docs: List[Dict[str, Any]]) -> None:
        """Store documents with embeddings"""
        from qdrant_client.models import PointStruct
        
        # Extract texts for embedding
        texts = []
        for doc in docs:
            text_parts = []
            if doc.get("title"):
                text_parts.append(doc["title"])
            if doc.get("description"):
                text_parts.append(doc["description"])
            if doc.get("content"):
                text_parts.append(str(doc["content"]))
            texts.append(" ".join(text_parts) if text_parts else "")
        
        # Generate embeddings
        embeddings = await self._embedding_provider.embed(texts)
        
        # Create points
        points = []
        for i, doc in enumerate(docs):
            points.append(
                PointStruct(
                    id=doc.get("id") or f"doc_{i}",
                    vector=embeddings[i],
                    payload=doc,
                )
            )
        
        # Upsert to Qdrant
        self._client.upsert(
            collection_name=self.collection,
            points=points,
        )

Explanation: - Text extraction: Combines title, description, content - Embedding generation: Creates vector for each document - PointStruct: Qdrant point (ID, vector, payload) - payload: Metadata stored with vector - upsert: Inserts or updates points

Querying RAG Store

    async def query(
        self,
        query_text: str,
        filters: Optional[Dict[str, Any]] = None,
        top_k: int = 10,
    ) -> List[Dict[str, Any]]:
        """Query similar documents"""
        # Generate query embedding
        query_embedding = await self._embedding_provider.embed([query_text])
        
        # Build filter
        qdrant_filter = None
        if filters:
            from qdrant_client.models import Filter, FieldCondition
            conditions = []
            for key, value in filters.items():
                conditions.append(
                    FieldCondition(key=key, match={"value": value})
                )
            qdrant_filter = Filter(must=conditions)
        
        # Search
        results = self._client.search(
            collection_name=self.collection,
            query_vector=query_embedding[0],
            query_filter=qdrant_filter,
            limit=top_k,
        )
        
        # Format results
        return [
            {
                "id": hit.id,
                "score": hit.score,
                **hit.payload,
            }
            for hit in results
        ]

Explanation: - Query embedding: Converts query text to vector - Filter: Filters by metadata (e.g., org_id, project_id) - search: Finds similar vectors (cosine similarity) - limit: Returns top K results - Formatting: Returns documents with similarity scores
